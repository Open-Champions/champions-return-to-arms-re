**Summary: every area passes; one fault found and fixed (rows 3d, 6 and 7 pass only with it).** Hardcore mode and aiming by looking on together
(rows 3d, 6, 7) put two blocks of guest memory over each other: `fpaim.h` kept the aim block at `0xE0A00`, inside

message bytes (`0xE0B00`) are Hardcore's "drops left" word, so rooms with both modes went out of step in that word
from the first tick (`sdrops` 3 against 0), and the Hardcore counters read nonsense ("drops 65540"). Fix: the aim
block moved to `0xE0E00` (one constant in `tools/recomp/app/fpaim.h`, the only place the address is written).

alone was never affected.

## Notes (not failures of the matrix)

- **Elden Ring figures in a document.** `docs/issues/native-souls-combat.md` 3.1 has a table of approximate Elden Ring
  timings and ratios (roll invulnerability frames, poise ratios by enemy kind) beside our values. No file or value of
  the game's data is in the repository, but these are figures read from it; whether that table should stay is for the
  owner.
- **Three stray patch files are tracked**: `tools/recomp/app/app_main.cpp.orig`, `build.py.orig`, `build_win.py.orig`
  (left from a patch). Not removed here.
- **Build id inside another checkout**: a setup's workspace that lies inside some other git checkout (here: the
  scratch HOME was inside this repository) takes that checkout's commit and dirty mark ("6c07742+") instead of its
  `SOURCE_ID` (`app/buildid.py` asks `git -C ROOT rev-parse`, which walks up). A player whose home folder is a git
  repository would see the same. Comparing `git rev-parse --show-toplevel` with ROOT first would fix it; not changed.
- The Godot boss route prints `app command not known: music say` (a line of the route written for an earlier
  `music.gd`); harmless.
- The Windows program needs `names.tsv` and `symbols/` beside it for scripts that use names (a test aid only). A Mac
  host must register at the service by the address the VM reaches (not 127.0.0.1), or the launch never completes
  (the first two tries here; a harness mistake, as `local/winvm/tools/room-host.sh` already does it right).
