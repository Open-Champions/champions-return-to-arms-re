# Creature animation dispatch, every class (appendix A)

Generated by `python3 tools/scan_anim_dispatch.py --markdown local/anim-dispatch-scan.json`
from the scan of the user's own executable (SLUS-20973 US v2.00), 2026-10-17. Every row is
**Executed**: one original function run in `tools/ee_emu.py` with stubbed callees; read
[creature-animation-dispatch](creature-animation-dispatch.md) section 2 for the method and
its limits, and use `tools/ref_creature_dispatch_data.py` (the same numbers) in code.
Names after an entry index are the resource identifiers stored at `def + 8k` of the first
definition listed; they are given to recognise roles, not to look clips up by name.

Format: `start(k name, blend, flags)`, `blend(k name, in/out, flags)` for
`anim_startBlendInOut`; `slotN` a virtual call on the creature (`slot27(s)` re-dispatches
state s), `holder.slotN` one on the weapon holder at `+0x50`; `sync` =
`anim_syncToSimFrame`, `jump_end` = `anim_jumpTopToEnd`. Stored `=` means the requested
number is written to `+0x232`. Choice lists recorded alternatives: `rand % p → entries per
residue`; `+off=v` a creature word and `[addr]=v` a global set alone on a zero creature;
`callees return object` the branch taken when every stubbed callee returns a non-null
object. A condition on a handle or pointer field shows the branch with stubbed lookups,
not its full effect (for example Horsemen `+0x3c8`, the mount handle). Flags: LOOP 1,
PURGE 2, END 4, ACT 8, HIT 0x10, TALK 0x20, FIXED 0x40, EASE 0x100, KEEP 0x200,
ROOT 0x800, PERSIST 0x1000, PAUSED 0x2000, YAW 0x4000. Events are `mask@seconds` (the
constructor's four slots per clip); event consumers are calls or creature stores that
appear only with that mask (`any event` = with every mask; `event word` = the callee is
handed the whole word); clip-status transitions are setState requests made only when the
union `+0x11a` is clear (marker ended) or set. States without a row are the switch
default (see `DISPATCH[class]['default']`).
