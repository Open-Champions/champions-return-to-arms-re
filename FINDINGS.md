# Findings ledger — Champions: Return to Arms (SLUS-20973 v2.00)

Each row says what kind of claim it is. "Observed" = read directly from the bytes at the
address given. "Inferred" = follows from observations but not seen happening. "Unknown" =
not established; the note says what would settle it. Nothing here was observed on a
running game.

Paths under `scripts/`, `decomp/` and `extracted/` are files you generate locally from your
own disc with the tools in this repository; they are not part of it.

## Stale pointers and address dependence

From `docs/issues/stale-pointers.md` and `tools/rawptr.py`: 478 virtual tables and about 490
pointer fields examined (the arena classes and 35 further fields by hand, the rest by the
scanner only). The class does not explain the every-run arena desync: the pool turns out to
be lockstep state apart from the one block of the prediction copy, so a stale pointer reads
the same bytes on every machine. Four one-word hardening changes for the plain pointers
(0x1b8fbc, 0x2f4518, 0x2f563c, 0x2c53a0) are described in the document and are deliberately
not in the patch file: they change the simulation for every player and address no known cause.
